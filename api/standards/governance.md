# Veydeck API 治理规范

## 1. 新接口

1. 明确领域、调用方和所属服务。
2. 按设计规范确定路径、方法和错误语义。
3. 写入 OpenAPI，状态设为 `missing`。
4. 完成实现和测试。
5. 核对后改为 `verified`，填写 `reviewedAt`。

## 2. 现有接口

- 首次登记设为 `unverified`。
- 契约与实现一致后设为 `verified`。
- 发现不一致时设为 `drifted`，在 `notes` 写明差异。
- 不确定字段保持宽松，不得按推测补全。

## 3. 变更

- 兼容变更：新增可选字段、新增响应状态、新增接口。
- 破坏性变更：删除或重命名字段、修改类型、修改路径或语义。
- 破坏性变更必须新增版本或完成调用方同步迁移。
- 实现变更和契约变更必须在同一工作项完成。

## 4. 废弃

1. 设置 `deprecated: true`。
2. `lifecycle` 改为 `deprecated`。
3. `notes` 写明替代接口和移除条件。
4. 调用方完成迁移后才允许删除。
5. 删除后保留历史记录，`lifecycle` 改为 `removed`。

## 5. 核对

核对至少检查：

- 方法和路径
- 参数位置与必填项
- 请求和响应字段
- HTTP 状态与业务错误码
- 认证要求
- Master/Agent 边界
- 源码位置和设计文档

`verified` 仅表示与核对日期时的实现一致。

## 6. 职责

- 接口作者负责契约和实现同步。
- 模块维护者负责设计审核与状态确认。
- 调用方发现偏移时必须标记 `drifted`，不得只在客户端兼容。
- `veydeck-docs/api` 是组织级唯一治理来源。

## 7. 校验

提交前执行：

```bash
pnpm validate
pnpm check
```

校验失败不得合并。第一阶段允许手动执行；后续接入 CI 时沿用同一命令。
