# Veydeck 分布式部署与节点管理路线图

本文档记录 Veydeck 在单主控、多节点场景下的架构路线、实现状态与后续规划，覆盖 `veydeck`、`veydeck-agent`、前端、部署链路与运维工具。

> [!NOTE]
>
> - `[x]` 表示该设计已在当前代码中 100% 落地实现。
> - `[ ]` 表示该设计目前属于预留或中后期路线图规划，代码尚未落地。
>
>   新功能开发或重构需要先更新本文档中的路线图状态。

---

## 1. 文档目标

### 1.1 设计目标

- [x] 定义 `Veydeck` 分布式多机架构的唯一标准模型。
- [x] 统一 `veydeck` 与 `veydeck-agent` 的职责边界、身份模型、通信方式与生命周期。
- [x] 为后续后端接口、前端交互、部署流程、数据库模型和测试策略提供稳定规范。

### 1.2 适用范围

- [x] 单主控 `veydeck`
- [x] 多节点 `veydeck-agent` (以下简称 `agent`)
- [x] Web UI 控制台
- [x] HTTP API 与 WebSocket 代理
- [x] SSH 自动化安装与预检
- [x] 节点注册、心跳续租与注销
- [ ] 证书在线自动轮换机制
- [x] 安全、审计、证书与可观测性

## 2. 架构总览

### 2.1 总体架构原则

- [x] `veydeck` 是唯一控制面与唯一入口。
- [x] 前端只能访问 `veydeck`，不能直接访问任意 `agent`。
- [x] `agent` 是节点执行面，只接受 `veydeck` 管理。
- [x] 运行时路由必须基于节点的活跃注册会话。
- [x] 部署与注册是两个独立阶段。
- [x] 节点在线状态以心跳与租约驱动。
- [x] 查询接口必须无副作用。

### 2.2 核心设计原则

- [x] **单一真相源**：所有节点状态、身份、路由信息由 `veydeck` 统一管理。
- [x] **显式身份绑定**：节点身份、证书、运行时会话必须建立一一绑定关系。
- [x] **控制面与数据面分离**：编排与执行、库存与运行态、部署与注册分离建模。
- [x] **安全默认开启**：所有跨主机通信默认启用 TLS/mTLS，节点必须经过受控纳管。
- [x] **面向审计设计**：部署、注册、续租、代理、任务、证书操作必须可审计。

## 3. 组件职责

### 3.1 `veydeck` (控制面) 职责

- [x] 单用户管理员认证与服务端会话控制。
- [x] 节点库存管理与分组标签管理。
- [x] 节点首次纳管、身份分配、证书信任管理。
- [x] 在线会话与租约定时回收管理。
- [x] 节点 HTTP / WebSocket 统一代理。
- [x] 任务调度、下发、结果汇总。
- [x] 事件、审计、告警与观测聚合。
- [ ] 分布式证书自动轮换调度。

### 3.2 `agent` (执行面) 职责

- [x] 暴露本机系统、容器、文件、进程、终端等能力。
- [x] 启动后主动向 `veydeck` 发起注册。
- [x] 周期性心跳并上报自身能力与运行时状态。
- [x] 接受 `veydeck` 转发的 HTTP 与 WebSocket 请求。
- [x] 持久化本地身份、证书与必要运行配置。
- [x] 执行本地采样并提供缓存视图。

### 3.3 前端 (Web UI) 职责

- [x] 只通过 `veydeck` 提供的控制面 API 访问系统。
- [x] 选择目标节点时，显式以节点标识作为 API 路由的一部分。
- [x] 不通过 query、header 或前端本地状态隐式选择目标节点。
- [x] 展示节点生命周期状态、会话状态、观测信息与任务结果。

### 3.4 运维工具职责

- [x] 负责节点安装、升级、修复、卸载与重装。
- [x] 负责生成、下发和写入纳管引导信息。
- [x] 不承担节点在线状态的判断与维护。

## 4. 节点生命周期模型

### 4.1 生命周期状态定义

- [x] `draft`：节点已建档，尚未部署。
- [x] `deploying`：节点正在安装、升级或修复。
- [x] `deploy_failed`：部署流程失败，未进入可纳管状态。
- [x] `awaiting_registration`：节点进程已启动，等待完成首次注册。
- [x] `registered`：节点身份已建立，但当前无活跃租约。
- [x] `online`：节点存在活跃会话，心跳正常。
- [x] `degraded`：节点在线，但能力或健康状态部分异常。
- [x] `offline`：节点租约失效或主动下线。
- [x] `unreachable`：节点探测失败，无法确认当前业务可用性。
- [x] `conflict`：节点存在角色冲突、身份冲突或重复会话冲突。
- [x] `retired`：节点已退役，不再参与调度和代理。

### 4.2 状态语义约束

- [x] 只有 `online` 与 `degraded` 节点可参与运行时代理。
- [x] 只有 `online` 节点默认可参与任务调度。
- [x] `deploying`、`deploy_failed`、`awaiting_registration` 属于部署与纳管阶段状态。
- [x] `registered`、`online`、`degraded`、`offline`、`unreachable` 属于运行阶段状态。
- [x] `conflict` 与 `retired` 属于限制性状态。

### 4.3 状态迁移规则

- [x] 创建节点后进入 `draft`。
- [x] 开始部署后进入 `deploying`。
- [x] 部署失败进入 `deploy_failed`。
- [x] 部署完成并成功启动 `agent` 后进入 `awaiting_registration`。
- [x] 首次注册成功后进入 `registered` 或 `online`。
- [x] 租约建立且心跳正常后进入 `online`。
- [x] 在线但能力异常时进入 `degraded`。
- [x] 租约过期或主动注销后进入 `offline`。
- [x] 探测失败时可转为 `unreachable`。
- [x] 检测到主控冲突、身份冲突或多会话冲突时进入 `conflict`。
- [x] 手动退役后进入 `retired`。

### 4.4 时间字段规范

- [x] `registered_at`：首次注册成功时间。
- [x] `last_heartbeat_at`：最近一次有效心跳时间。
- [x] `last_seen_at`：最近一次节点成功与 `veydeck` 建立受信通信的时间。
- [x] `last_probe_at`：最近一次后台探测完成时间。
- [x] `last_deploy_at`：最近一次部署流程完成时间。

## 5. 身份与信任模型

### 5.1 身份模型

- [x] `node_id` 是控制面主键，生命周期稳定。
- [x] `agent_id` 是节点运行时身份，必须与一个 `node_id` 绑定。
- [x] 一个活跃节点只能拥有一个有效运行时身份。
- [x] 一个运行时身份在同一时刻只能对应一个活跃会话。

### 5.2 首次纳管模型

- [x] `veydeck` 为待纳管节点生成一次性 `enrollment token`。
- [x] `enrollment token` 必须具备过期时间、一次性使用约束与节点范围约束。
- [x] 首次注册时，`agent` 使用 `enrollment token` 发起受控纳管请求。
- [x] `veydeck` 校验成功后建立 `node_id` 与 `agent_id`、证书和会话关系。
- [x] `agent` 在 enrollment/register/heartbeat 请求中必须携带自身版本、runtime 协议版本与最低主控版本要求。
- [x] `veydeck` 在 enrollment/register/heartbeat 响应中必须返回主控版本、runtime 协议版本、最低 agent 版本要求与兼容结论。
- [x] 双方必须在运行时注册与续租链路执行双向兼容校验，任一方向不兼容时不得继续建立或刷新会话租约。

### 5.3 证书与 mTLS 约束

- [x] 系统使用私有 CA 管理节点受信通信。
- [x] `veydeck -> agent` 的所有运行时请求必须启用 mTLS 双端校验。
- [x] `agent -> veydeck` 的注册与续租请求必须建立受控身份链路。
- [x] 所有证书必须记录指纹、签发时间、过期时间与状态。
- [x] 非受管证书与匿名节点不得接入系统。

### 5.4 证书轮换

- [x] 提供 `/rotate-certificate` 证书轮换接口。
- [x] 轮换前必须验证当前节点身份与会话合法性。
- [ ] 计划轮换与强制轮换的完全自动化全链路调度与下发。
- [x] 轮换后必须更新证书指纹绑定关系。
- [x] 轮换失败不得破坏已存在的有效身份关系。

## 6. 部署模型 (Provisioning)

### 6.1 部署与标准安装

- [x] 安装 `agent` 二进制，写入节点运行配置，创建标准目录结构。
- [x] 注册并启用 systemd 服务，启动 `agent` 并使其进入 `awaiting_registration`。
- [x] **SSH 推送式部署**：支持远程输入 SSH 密钥/密码，由控制面自动推送并安装。
- [x] **强权限与安全性预拦截**：强行拒绝不具备免密 `sudo` 权限的普通用户和非 root 用户，在部署极前置阶段立即拦截并抛出终止报错，彻底防止交互式密码死锁。
- [ ] **架构自适应分发**：根据 SSH 检测到的目标节点 CPU 架构（x86_64、aarch64），主控自动检索、匹配或动态下载对应架构的 `veydeck-agent` 二进制包。当前阶段硬性校验仅支持 `x86_64` 异构并进行部署前强拦截。
- [ ] **预装节点纳管与离线安装包部署**：本地手动运行脚本拉起纳管。

### 6.2 预检规范

- [x] SSH 连通性与用户 sudo 权限检查。
- [x] systemd 可用性与目标目录可写性检查。
- [x] 运行端口占用检查与 Docker 环境预检。
- [x] **节点复用与冲突检测**：新增节点流程必须采用严格复用策略，禁止仅凭 `veydeck-agent` 文件、二进制、systemd 服务或配置文件存在就判定“可复用”。
- [x] **归属校验**：发现目标主机已存在 `veydeck-agent` 时，必须读取标准安装产物并识别 `agent_id`、`veydeck_url`、安装目录、角色标记与 agent 版本，再与当前主控数据库中的 `node_identities` / `nodes` 进行匹配。
- [x] **冲突分类**：预检必须区分干净目标机、当前主控已有节点、其他主控节点、残留安装、主控服务冲突、版本不兼容等状态，并给出明确阻断原因与建议动作。
- [x] **新增节点限制**：新增节点流程只允许干净目标机继续部署；当前主控已有 agent 也不得创建新的节点库存记录，必须提示该主机已由当前主控管理，避免一个 agent 对应多个节点。
- [x] **接管限制**：当前阶段不支持接管其他主控节点；检测到远端 `veydeck_url` 不属于当前主控时必须阻止新增、部署和复用。
- [x] **版本兼容约束**：版本解析与比较必须使用 SemVer 语义，不得使用字符串相等或手写拆分逻辑；当前 `0.x` 阶段默认采用保守兼容规则，要求主控与 `veydeck-agent` 的 `major`、`minor`、`patch` 与 prerelease 标识一致，后续 `1.x` 稳定版本再按明确兼容矩阵放宽同主版本内的 minor/patch 兼容范围。
- [x] **版本策略配置**：SemVer 兼容策略必须集中在主控配置层管理，不得散落在预检业务逻辑中；默认配置保留 `0.x` 精确兼容与稳定版本同主版本兼容规则，后续兼容策略调整只修改配置模型与默认值。
- [x] **版本兼容结果**：预检响应必须返回结构化版本兼容结果，至少包含主控版本、远端 agent 版本、是否兼容、拒绝原因与建议动作；版本不兼容时提示通过已有节点执行升级、修复或重装。
- [x] **二次检测**：部署接口在写入远端配置、覆盖二进制或重启服务前，必须重新执行节点复用与冲突检测，防止预检后目标状态变化导致误覆盖其他主控或已有节点。

### 6.3 标准安装产物

- [x] 二进制路径：`/usr/local/bin/veydeck-agent` 或 `/usr/bin/veydeck-agent`
- [x] 配置文件：`/opt/veydeck/config/agent.toml`
- [x] systemd 服务：`/etc/systemd/system/veydeck-agent.service`
- [x] 数据与运行目录：`/opt/veydeck/database`、`/opt/veydeck/logs`、`/opt/veydeck/run`

## 7. 注册与续租协议 (Runtime API)

### 7.1 协议总则

- [x] 所有注册类接口定义在 `/api/v1/runtime/` 下。
- [x] 除首次 enrollment 注册外，所有接口均使用已绑定的受信证书。
- [x] 请求与响应统一使用 JSON，时间使用 RFC 3339 UTC，ID 使用 UUID v7。
- [x] 注册、心跳与注销接口均具备天然的幂等性逻辑。

### 7.2 API 落地追踪

#### 7.2.1 首次注册 Enrollment

- [x] **接口**：`POST /api/v1/runtime/enroll`
- [x] 校验 token 合法性、未过期、未使用。
- [x] 校验 agent 版本与 runtime 协议兼容性。
- [x] 成功后写入 `node_identities`、创建活跃 `session` 并返回证书与配置。

#### 7.2.2 非首次注册 Register

- [x] **接口**：`POST /api/v1/runtime/register`
- [x] 允许节点重启、网络切换后恢复活跃会话。
- [x] 校验证书指纹与 `agent_id` 匹配性，优雅覆盖并清理旧会话。
- [x] 校验 agent 版本与 runtime 协议兼容性，并在响应中返回主控兼容声明供 agent 反向校验。

#### 7.2.3 心跳续租 Heartbeat

- [x] **接口**：`POST /api/v1/runtime/heartbeat`
- [x] 延长会话租约（Lease TTL = 30s，心跳间隔 = 10s，主控过期会话回收扫描间隔 = 5s）。
- [x] 上报硬件（CPU/内存）负载与节点能力状态。
- [x] 每次 heartbeat 必须携带 agent 兼容声明；主控拒绝不兼容 heartbeat，agent 也必须校验响应中的主控兼容声明。
- [x] 主控不可达时，agent 按 3s、6s、12s、20s 上限指数退避重连，并附加 0-3s jitter。
- [ ] 心跳响应中携带并下发运行时控制命令 (`commands`)。
- [ ] **控制面网络配置实时同步**：当全局 `VEYDECK_PUBLIC_HOST` 发生变化时，心跳响应通过指令将新的 `veydeck_url` 下发至 Agent，引导其修改本地配置文件并优雅热重启。

#### 7.2.4 主动注销 Deregister

- [x] **接口**：`POST /api/v1/runtime/deregister`
- [x] 节点优雅下线，释放会话与租约，节点置为 `offline`。

## 8. 运行时通信代理 (Proxying)

- [x] **统一访问原则**：所有节点能力必须经由 `veydeck` 暴露，前端绝不直连 Agent。
- [x] **HTTP 代理中继**：控制面解析 `node_id`，定位活跃会话，代理透传 HTTP 业务接口。
- [x] **WebSocket 代理中继**：通过 `veydeck` 发起 WS 协议升级，中继实时 shell 和日志数据流。
- [x] **会话隔离**：每个节点在同一时刻只能有一个活跃会话，出现多重会话时自动吊销旧会话。

---

## 9. 节点能力与可观测性

### 9.1 能力模型

- [x] 节点支持声明能力集：`system`、`docker`、`filesystem`、`process`、`terminal`。
- [x] `veydeck` 根据上报的能力集决定前端控制台的 UI 模块可见性。

### 9.2 健康检查与观测

- [x] **注册监控**：检测租约是否过期，过期由租约回收机制重置为 `offline`，离线收敛窗口通常为 30-35s。
- [x] **指标快照**：心跳持续收集 CPU、内存、网络、Docker 状态快照并入库。
- [x] **后台探测**：提供后台主动异步健康探测逻辑。
- [x] **状态交互限制**：在前端控制台节点切换列表中，对非 `online`/`degraded` 状态的异常节点限制点击或禁止切换，引导用户至“节点管理”中进行修复。

## 10. 数据模型规范 (Database Schema)

- [x] 数据库物理表遵循严格的分表设计约束：
  - `nodes`：保存节点静态资产档案。
  - `node_provisioning`：保存 SSH 等安装部署信息。
  - `node_enrollments`：保存一次性纳管 Token 状态。
  - `node_identities`：保存 agent_id、证书指纹及状态。
  - `node_sessions`：保存运行时 IP、端口、Lease 过期时间。
  - `node_observations`：保存观测与硬件性能快照数据。
  - `node_tasks`：保存节点异步调度任务。
- [x] 字段命名符合 `_at` 时间后缀，`_seconds` / `_percent` 数值单位后缀约束。
- [x] 建立关键唯一性约束与联合索引，确保高并发注册下 session 数据不冲突。

## 11. 安全与审计规范

- [x] **基本安全要求**：默认启用 TLS/mTLS，默认身份认证，默认最小权限。
- [x] **凭据保护**：SSH 密码/密钥加密后落盘。纳管 token 采用 SHA-256 摘要哈希存储。
- [x] **审计覆盖**：以下高敏感操作全部写入主控数据库审计表中，实现全链路追溯：
  - 节点创建与修改。
  - 部署、升级、修复、卸载。
  - 首次 Enrollment 注册、续租、Deregister 注销。
  - 节点 HTTP / WebSocket 代理请求中继。

---

## 12. 运维与故障恢复

- [x] **常规运维操作**：控制面提供一键安装、升级、修复、卸载、退役操作。
- [x] **故障自动重连**：Agent 宕机重启后利用本地身份自动发起重连，主控平滑接管。
- [x] **多端冲突保护**：同一节点同时存在双活心跳或指纹不匹配时进入 `conflict` 状态，拒绝代理。

---

## 13. 实现与开发约束

- [x] **状态查询无副作用**：所有 GET 与只读 API 不得更改数据库会话与租约记录。
- [x] **路由动态查找**：控制中继路由必须动态查询当前活跃 `session` 表，禁止将部署时的静态 IP 作为直接访问入口。
- [x] **部署与在线状态隔离**：部署任务完成仅表示配置和进程落盘成功，不表示节点在线，必须等待 Agent 主动发起 Heartbeat 注册。
